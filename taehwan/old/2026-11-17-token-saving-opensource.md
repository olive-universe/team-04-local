# AI 작업 토큰 절약 오픈소스 조사

확인일: 2026-11-17. 공식 저장소 README 확인 기준. 설치하거나 설정을 바꾸지는 않았다. 광안대교 작업은 중단 상태로 유지한다.

| 후보 | 줄이는 대상 | 현재 작업에 대한 판단 | 공식 출처 |
|---|---|---|---|
| RTK | git·검색·테스트 등 CLI 출력의 불필요한 줄 | 터미널 출력에 적용하기 쉬운 후보. Roblox MCP 응답까지 자동 압축된다고 판단하지 않음 | https://github.com/rtk-ai/rtk |
| context-mode | 큰 파일·명령·도구 출력을 로컬에 보관하고 필요한 내용 검색 | 긴 문서와 도구 응답이 많은 작업에 유용할 후보. 실제 클라이언트의 훅과 출력 전달 방식은 설치 전 확인 필요 | https://github.com/mksglu/context-mode |
| Serena | 코드 전체 대신 함수·클래스·참조 단위의 의미 기반 탐색 | 코드 규모가 커질 때 유용. README는 Lua/Luau 지원을 명시하지만 현재 Studio의 실시간 데이터모델과 자동 동기화되는 것은 검증하지 않음 | https://github.com/oraios/serena |
| LLMLingua | 긴 텍스트 프롬프트 자체 압축 | 자체 API/RAG 파이프라인에 더 적합한 후보. 압축용 모델 실행과 품질 비교 필요 | https://github.com/microsoft/LLMLingua |

## 확인한 제약

- RTK는 명령 출력 절감과 전체 비용 절감이 다르다고 명시한다. 원문 우회/복구와 자체 통계 기능을 제공한다. Windows 설치 및 Codex용 연동 안내가 있으나 현재 세션에서의 적용은 검증하지 않았다.
- context-mode는 Windows에서 Git for Windows를 요구하고, Node 버전 요건과 클라이언트별 설정이 있다. README의 대표 성능 수치는 큰 출력의 컨텍스트 유입 바이트를 측정한 벤치마크이며 전체 청구 토큰 절감 보장이 아니다.
- Serena는 MCP로 심볼 단위 탐색/편집을 제공한다. 작은 파일이나 기하 모델링·이미지 검수 중심 작업에서는 추가 도구 도입의 이득이 작을 수 있다(판단).
- LLMLingua는 단어/토큰을 선별하는 프롬프트 압축 계열이다. 원문 정보가 중요한 코드·요구사항에는 결과 정확도 비교가 필요하다(판단).

## 권장 적용 순서

먼저 반복적인 문서 전문 출력과 불필요한 전체 코드 재출력을 줄인다. 그다음 터미널 위주면 RTK, 큰 문서/도구 응답 위주면 context-mode를 하나만 시험한다. 같은 대표 작업에서 입력 토큰·실패/재작업·실제 사용 비용을 비교한 뒤 유지 여부를 결정한다. 현재 실제 토큰별 사용 내역은 계측하지 않았으므로 정확한 절감률을 약속할 수 없다.
