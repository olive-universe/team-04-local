## 정해서 적어 둔 기준 (정답이 없는 것)

1. 글이 마침표(`.`) 하나뿐인 카카오맵 후기 2건(21행 2026-04-08, 47행 2025-09-10)은 "글이 있는 후기"로 치지 않는다. 다만 파일에 이미 들어 있으므로 지우지 않고 그대로 둔다. 그래서 글로 읽을 수 있는 후기는 98건이다.
2. 무엇에 대한 말인지 없이 전체 칭찬·불만만 있는 짧은 글(예: "국내 온천 1티어"(95))은 넣는다. 다만 태그는 붙이지 않는다(`review-codebook.md`).
3. 등록일은 후기를 쓴 날로 본다. 방문한 날이 아니다.
4. 카카오맵 100건은 허심청 후기 중 최신순 100건일 뿐이다. 허심청 전체나 동래온천 전체의 평가로 넓혀 말하지 않는다.
5. **체험단 글**: 업체에게 무료 이용이나 대가를 받고 쓴 글은 **빼지 않고 넣는다.** 대신 '광고·체험단 표시 있음/없음'을 적고, 분석할 때는 표시 있는 글과 없는 글을 따로 센다. 이유: 빼면 몇 건이 체험단이었는지조차 남지 않는다. 글에 표시가 없으면 "없음"으로 적고, 체험단인지 짐작해서 적지 않는다.
6. 네 곳은 모은 방식과 건수가 달라서 숫자를 서로 더하거나 비율로 견주지 않는다. 같은 말이 여러 곳에서 나오는지만 본다.

## 원본 파일 이름 규칙 (2026-11-17 정함)

모은 원본은 갈래별 폴더에 둔다: 글 `raw/text/`, 영상 `raw/video/`, 사진 `raw/image/`. `raw/`는 내 PC에만 두고 git에 올리지 않는다.

```
모은날_소스_장소_내용.확장자
```

| 칸 | 쓰는 법 | 예 |
|---|---|---|
| 모은날 | YYYY-MM-DD | `2026-11-16` |
| 소스 | 어디서 모았나 (한국어) | `구글맵`, `네이버블로그`, `유튜브` |
| 장소 | 우리 장소 | `광안리` |
| 내용 | 무엇인지 + 원문/번역본 같은 구분 | `외국어리뷰-원문` |

- 칸 사이는 `_`(밑줄), 한 칸 안에서 낱말을 이을 때는 `-`(빼기)를 쓴다.
- 띄어쓰기는 쓰지 않는다(터미널에서 경로가 깨지기 쉬움).
- 예: `raw/text/2026-11-16_구글맵_광안리_외국어리뷰-원문.txt`
