# 리서치 노트 틀 (research-note)

- 근거: 2026-11-19 노트들이 따른 틀이다. 예: `research/2026-11-19-광안대교-조명-2026.md`, `research/2026-11-19-광안리-평소-손님불편.md`, `research/2026-11-19-광안리-축제아닌-자료-정리.md`
- CLAUDE.md 4절 규칙이 이 스킬보다 먼저다. 출처를 다시 확인하는 일은 `source-verify` 스킬을 쓴다.

## 순서

1. **질문 한 줄 정하기**: 무엇을 알고 싶은지, 왜 필요한지(어느 파일의 어느 칸을 채우려는지) 사용자에게 먼저 말한다.
2. **이미 있는 것부터**: `research/`, `inventory/`, `inputs/`, `archive/metadata.csv`에서 같은 이야기를 먼저 찾는다. 있으면 새로 찾지 않고 그 노트를 가리킨다.
3. **찾기**: 웹 검색 → 고른 페이지는 **직접 연다**. 검색 결과 요약만으로 쓰지 않는다. 언어(한·영·일·중)를 나눠 찾으면 노트 머리말에 적는다.
4. **노트 쓰기**: 아래 틀. 파일 이름은 `research/YYYY-MM-DD-주제.md`(오늘 날짜, 한글 주제 가능).
5. **보여 주고 커밋**: 한 줄 판단과 못 찾은 것을 사용자에게 먼저 보여 준 뒤 커밋한다. 노트가 커지면 "1단계·2단계"로 나눠 커밋한다.

## 노트 틀

```markdown
# (무엇) · (한 줄 범위)

- 작성: 전태환 (Claude 도움) · 확인한 날: YYYY-MM-DD
- 왜: (어느 파일의 어느 칸을 채우려고. 예: brand/bible/conflicts.md CON-05 갈등 칸)
- 방법: (웹 검색 언어 · 직접 연 페이지 수 · 크롬으로 연 것)
- 읽은 파일: (폴더 안 파일)

## 1. 확인한 원문

| 무엇 | 원문(글자 그대로) | 누가 · 어디 | 날짜 | URL |
|---|---|---|---|---|

- (한 출처뿐인 줄 표시: "○○ 보도에 따르면")
- (값이 다른 줄: 둘 다 적음)

## 2. 찾지 못한 것 · 열지 못한 것

- (무엇) [확인 필요: 어디서 확인할지]

## 3. 한 줄 판단

- (이 노트로 말할 수 있는 것)
- 가설: (자료로 말할 수 없는 해석)
```

## 지킬 것

- inputs/ 숫자는 파일 이름 + 엑셀 행 번호(머리줄 = 1행)를 붙이고 반올림하지 않는다.
- 리뷰·후기는 "이런 목소리가 있다"이지 "대부분이 그렇다"가 아니다. 건수를 함께 적는다.
- 사람 이름(닉네임 포함)과 얼굴 사진은 `collection-rules.md` '뺄 것'을 따른다. 언론에 실명으로 나온 인터뷰는 보도 출처와 함께만 쓴다.
- 해마다 바뀌는 값(시간·가격·일정)은 연도를 함께 적는다. 예: "점등 시간(2022 자료)".
