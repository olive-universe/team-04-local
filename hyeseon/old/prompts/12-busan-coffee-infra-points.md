# 할 일 2 · 빈 곳 찾기
표를 보고, 단계와 단계 사이에서 '부산에 없어서 물건이나 돈이 수도권으로 빠지는 지점'을 모두 적는다.
빈 곳마다 아래를 적는다.
- 무엇이 없는가 (한 줄)
- 근거 (할 일 1 표의 어느 줄인지)
- 누가 불편한가 (카페 사장님 / 로스터리 / 수입사 / 부산시 등)
- 이미 메우려는 곳이 있는가 (HTML의 사례 9개 + 새로 찾은 것)

# 할 일 3 · 우리가 파고들 포인트 고르기
빈 곳마다 아래 다섯 기준으로 1~5점을 준다. 점수마다 이유를 한 줄 붙인다.
1. 문제 크기: 근거 숫자가 있는가, 얼마나 큰가
2. 근거 확실성: 원문을 확인한 출처인가
3. 데이터 접근: 공공데이터나 현장 인터뷰로 6주 안에 직접 모을 수 있는가
4. 6주 실현성: 개발 1명·예산 없음으로 시연까지 갈 수 있는가 (물류·정산·법적 책임이 없어야 높음)
5. 차별성: 영도 클러스터, 모모스, 코케비즈 등 기존 시도와 겹치지 않는가
합계 상위 3개를 '파고들 포인트'로 고르고, 각각 아래를 적는다.
- 한 줄 정의
- 왜 지금 우리 팀인가
- HTML의 MVP 후보 1~4와 어떻게 이어지는가 (그대로 / 바꿈 / 새 후보)
- 1주차 확인 질문 3개 (인터뷰나 데이터로 맞는지 틀린지 판가름 나는 질문)
- 이지 님·태환 님 기획과 겹치는 점

# 지킬 규칙
- 숫자, 날짜, 업체 이름에는 출처를 붙인다. 출처가 없으면 [확인 필요]로 적는다.
- HTML에서 "원문 미확인"인 수치는 다시 확인하기 전까지 [2차 인용]이라고 적는다.
- 내가 판단한 것은 [내 판단], 제안은 [제안]이라고 붙인다.
